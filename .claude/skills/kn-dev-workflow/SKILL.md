# 開発フロー

## 目的

仕様はユーザーが決め、受け入れ要件をテストで固定し、実装を受け入れ要件から隔離することで、仕様どおりの実装と、ユーザーが理解したうえでのマージを両立させる。委譲は隔離が必要なときだけにして、速度とトークン効率を保つ。

## 参照

- ルール本体は `references/rules.md`。開発タスクに着手する前に必ず読むこと(関連スキルとの分担も rules.md に書いてある)。

## 実行手順

1. `references/rules.md` を読む
2. タスクの文書(kn-task-docs の配置)を確認し、フローのどの段階にいるかを判断する
3. rules.md の「フロー」の段階を順に進める。小さな修正は「軽量ルート」(運用ルートのタスクでは「運用ルートの小さな修正」)、スキル・hook・設定・ドキュメントだけを変えるタスクは「運用ルート」の条件を満たすか判断する
4. 仕様の疑問は rules.md の「エスカレーション」に従い、決定を design.md に転記してから再開する
5. PR を作る前に、理解度チェックを終えていることを確認する
